# 导入工具说明

`PhotoImportGUI.ps1` — 把照片按相机与拍摄时间自动归档。

## 启动

```powershell
# 图形界面
powershell -ExecutionPolicy Bypass -File .\src\app\PhotoImportGUI.ps1 -TargetRoot "D:\照片库"

# 命令行版（同目录另见 PhotoCore.ps1 的 API）
```

参数：`-TargetRoot <照片库路径>`，缺省为用户「图片」目录下的 `照片库`。

## 归档规则

```
照片 → <库>\<相机>\<年>\<年-月>\    例: D:\照片库\01-A7M4\2026\2026-01\DSC_0001.JPG
视频 → <库>\<相机>\视频\
日期无效（早于 2001-01-01） → <库>\99-日期异常\
认不出相机 → <库>\09-未识别相机\
```

相机文件夹名由 `PhotoCore.ps1` 顶部的 `CamRules` 决定，可按需扩展：

```powershell
CamRules = @(
    [pscustomobject]@{ Folder='01-D7200'; Model='d7200'; PathTag='d7200'; MinNum=3000; MaxNum=9999 }
    [pscustomobject]@{ Folder='02-Z62';   Model='z\s*6_2|z6_2|z\s*6ii|z6ii'; PathTag='nz6|z62|z6_2'; MinNum=1; MaxNum=2999 }
)
```

新增相机时补一条即可：`Model` 匹配 EXIF 型号（正则），`PathTag` 匹配卡片目录名，
`MinNum/MaxNum` 是文件编号兜底区间。

## 相机识别顺序

1. EXIF 机身型号（`NIKON D7200` / `D7200` / `NIKON Z 6_2`）
2. 源目录名（`100D7200`、`100NZ6_2` 这类相机生成的文件夹）
3. 文件编号区间（最后兜底）

## 日期识别

1. EXIF 拍摄时间
2. 文件修改时间（视频通常没有 EXIF）

> 不要用「创建时间」——那是拷贝时间，会全错。

## 判重

| 情况 | 处理 |
|---|---|
| 目标已存在同名、同大小、修改时间一致 | 跳过（快速模式） |
| 目标已存在同名、大小一致但时间不同 | 计算 MD5 比较，相同则跳过 |
| 目标已存在同名但内容不同 | 自动改名 `xxx_1.JPG`（保留原扩展名大小写） |

## 并发

复制阶段用 C# 线程池并发。实测在单块 USB 机械硬盘上**单线程最快**
（82.9 MB/s，达裸盘写速 98%），多线程会因寻道竞争变慢。
仅在源与目标分处不同物理盘（SSD）时，才建议调高线程数。

## EXIF 扫描

不走 Windows Shell COM，而是直接解析文件头（C# 实现），可并行：

| 方式 | 每文件 |
|---|---:|
| Shell COM 串行 | 27.9 ms（冷读 220 ms） |
| 自研 1 线程 | 8.4 ms |
| 自研 4–8 线程 | 0.2 ms |

## 后台线程

导入在独立 runspace 中执行（STA），界面线程每 150 ms 收消息刷新，
因此几千个文件也不会「未响应」，且可随时取消。

## 日志

每次真正导入会追加写入 `<库>\_工具\导入日志.csv`，列为：
时间、原路径、新路径、结果、备注。

## 相关文件

| 文件 | 作用 |
|---|---|
| `PhotoImportGUI.ps1` | 界面与事件 |
| `PhotoCore.ps1` | 判定与搬运的核心函数（被界面和 worker 共用） |
| `PhotoWorker.ps1` | 后台工作线程：并行 EXIF + 并发复制 |
| `PhotoLib.ps1` | C# 实现的 EXIF 解析与缩略图提取（管理端也用） |
