# 照片管理器说明

`PhotoManagerGUI.ps1` — 浏览、筛选、评分、标记本地照片库。

## 启动

```powershell
powershell -ExecutionPolicy Bypass -File .\src\app\PhotoManagerGUI.ps1 -Root "D:\照片库"
```

参数 `-Root` 缺省为用户「图片」目录下的 `照片库`。

## 索引

启动时自动加载 `_缓存\index.json`，并在后台做一次增量检查（约 2 秒）。
只处理新增 / 修改 / 删除的文件，其余直接复用记录。

比对依据：**相对路径 + 文件大小 + 修改时间**。三项都没变就跳过，不重读 EXIF、不重做缩略图。

| 场景 | 耗时（约 7500 项） |
|---|---:|
| 全量重建 | 153 秒 |
| 无变化检查 | 2.6 秒 |
| 新增 1 张 | 2.7 秒 |

界面按钮：

- **更新索引**：增量（日常用）
- **完全重建**：忽略旧索引全部重读（升级或怀疑数据异常时用）

## 缩略图

优先直接提取 JPEG 内嵌的 EXIF 缩略图（约 160×120，位于文件头 64 KB 内），每张约 12 ms。
没有内嵌图时回退 WIC 按目标宽度解码。NEF 优先复用同名 JPG 的缩略图。

缓存位于 `_缓存\thumbs\`，文件名是「源文件相对路径」的 MD5。
每次建索引结束会清理未被引用的孤立缩略图。

## 评分与标记

快捷键：`1`–`5` 打星、`0`/`U` 清除、`X` 淘汰、`P` 保留、`←`/`→` 上下张、`PageUp/Dn` 翻页。

标记存放在 `<库>\_缓存\marks.json`，**与索引分离**，因此重建索引不会丢标记：

```json
{"2026\\2026-01\\DSC_0001.JPG":{"r":4,"f":"keep"}}
```

- `r`：星级 0–5
- `f`：`keep` / `reject` / 空

> 标记按相对路径做键。在管理器之外移动或改名文件，对应标记会失联（不会报错，只是回到未评分）。

## RAW+JPG 合并

索引仍是逐文件记录，合并发生在界面层：按「目录 + 基名」归组，
一个格子显示 JPG 预览并标注 `RAW+JPG`。

- 打分/标记会写入组内**每一个**成员文件
- 删除时组内文件一起移入回收站
- 底部「分开显示 RAW 与 JPG」可切回逐文件视图

## 筛选

相机 / 年 / 月 / 文件名关键字 / 标记状态（未评分、≥3 星、≥4 星、保留、淘汰），可组合。

## 删除

「删除到回收站」使用 `Microsoft.VisualBasic.FileIO.FileSystem::DeleteFile(... SendToRecycleBin)`，
可在回收站还原。顶部另有「删除全部淘汰项」批量处理。

## 已知限制

- 只扫描单个照片库根目录
- 视频没有缩略图（显示 VIDEO 占位）
- NEF 不做 RAW 解码（用内嵌预览或同名 JPG）
- 搜索只匹配文件名
- 无标签、人脸识别、相似图去重
